# M10 — Complete Night Shift & Reception Computer

Рабочая сцена: `Assets/Game/Scenes/Motel_Blockout_V3.unity`.
Unity 6000.3.19f1, URP 17.3, NGO 2.13.3, Unity Transport 2.6.0.
Пакеты не менялись. Внешние модели, изображения, шрифты и звук не загружались.

## Полная смена вдвоём

1. Запустить `Builds/Playtest/LaunchWindowed.command` дважды, расположить окна 800 × 600 рядом. В первом выбрать **Start Host**, во втором **Start Client**; адрес `127.0.0.1`, порт `7777`. Альтернатива: Host в Unity Play Mode, Client в актуальном standalone. Обе стороны должны использовать M10.
2. Управление: WASD, мышь, Left Shift; **E** для взаимодействий. Esc вне терминала освобождает курсор для меню подключения. Пройти за стойку через открытый северный край Reception. Компьютер стоит на прежнем месте рядом с телефоном, экран обращён к сотрудникам.
3. Навести камеру на экран, нажать **E — Use Reception computer**, затем **Start Shift**. Камера приблизится за 0.3 с; персонаж останется на месте. После старта терминал освободится, камера вернётся в FPS. Время начинается с 22:00. До старта нет прибытий и уборки.
4. Подготовить номера 101–104: взаимодействовать с матрасом и двумя объектами мусора. Dirty → Ready только после всех трёх действий. Проверять состояния на табличках и новой доске в Utility.
5. Гости самостоятельно приходят с парковки. Через компьютер назначить гостю у первой позиции очереди свободный Ready номер. Остальные ждут на двух отдельных позициях. **Esc** или **Return to motel** возвращают камеру и управление. Второй игрок продолжает работать, пока первый использует компьютер.
6. На звонок ответить **E** у существующего телефона. Для **Clean Towel** взять полотенце в Utility и доставить к указанному номеру. Для **TV Repair** войти в этот номер: **E** на блоке кабеля слева от телевизора, затем **E** на регуляторе справа от экрана. Телевизоры стоят на существующих письменных столах.
7. Через 120 с после входа в номер гость возвращается на Reception. Номер остаётся Occupied до принятия ключа. В компьютере выбрать **Accept key / Check out Room…**. Номер станет Dirty, гость уйдёт пешком. Повторно убрать номер и заселить следующего гостя.
8. Через 15 реальных минут наступит 06:00. Новые задания прекратятся, незавершённая заявка отменится, гости вернутся в скрытый пул, появится общий итог. В компьютере выбрать **Start Next Shift**. Подключения сохраняются; комнаты, гости и заявки начинают новый цикл.

Для LAN указать адрес компьютера-хоста вместо localhost. Отдельная проверка между компьютерами требуется; Relay, Steam и host migration не реализованы.

## Смена и настройки нагрузки

`NightShiftController` на корне **NightShift** хранит одну server-write `ShiftSnapshot`: фазу, номер смены, начало и длительность, число прибытий и итоговые счётчики. Фазы: WaitingToStart → Running → Finished → Running.

Часы вычисляются из NGO `ServerTime`: реальные секунды линейно отображаются в интервал 22:00–06:00. Ежекадровых RPC для часов нет. Освещение не меняется.

| Inspector | Значение по умолчанию | Назначение |
|---|---:|---|
| Duration Seconds | 900 | Реальная длительность ночи |
| Arrival Count | 6–8 | Число запланированных прибытий |
| First Arrival Delay | 45 с | Нижняя граница первого прибытия |
| Last Arrival Fraction | 0.8 | После 80% смены новые гости не начинают маршрут |
| Workload Weights | (2, 3, 2) | Относительная плотность ранних, средних и поздних прибытий |
| ReceptionDesk.Arrival Patience | 120 с | Терпение прибывшего после достижения позиции ожидания |
| GuestLifecycle.Stay Duration | 120 с | Пребывание после физического достижения GuestIdle |
| GuestServiceRequests.Call Delay | 15 с | Задержка до заявки после входа гостя |
| Between Requests Delay | 8 с | Пауза перед выбором следующей заявки |
| Timing Variation | 0.3 | Случайное отклонение интервалов звонков |
| Television Chance | 0.5 | Вероятность TV вместо полотенца |

Сервер один раз создаёт стратифицированное случайное расписание. Используются пять существующих NPC и четыре номера; бесконечного создания гостей нет. Если пул или Reception заняты, прибытие ждёт допустимого окна. Неиспользованные слоты после cutoff не создают гостей и не считаются потерянными клиентами.

Один запрос на проживание, один активный звонок или задача глобально. Тип выбирается сервером, строгих квот полотенец и ремонта нет. Это исходная настройка нагрузки, а не результат внешнего балансировочного плейтеста.

## Очередь и существующая регистрация

`ReceptionDesk` расширен серверным списком длиной до трёх гостей. Точки настроены в сцене. `GuestSnapshot.QueuePosition` передаёт позицию очереди, фаза — подход или ожидание. Гости передвигаются через существующий NavMeshAgent. После обслуживания координатор даёт гостю отойти от стойки, затем продвигает следующего.

Обычный порядок FIFO. Единственное исключение: при полном заселении возврат ключа может пройти перед прибывшим гостем, которого сейчас невозможно поселить. Новые прибытия при полном заселении задерживаются. Это позволяет освободить номер без автоматического checkout. Терпение применяется только к прибывшим; возвращающиеся гости не исчезают по таймеру.

Проверки M4/M7/M9 сохранены: текущий гость, NetworkObject, Visit, RoomCycle, статус и допустимость комнаты. Дополнительно необходимы Running смена и действующая аренда компьютера (User/Lease). Повторный RPC не заселяет следующего гостя и не увеличивает статистику дважды.

## Компьютер, камера и интерфейс

Существующие ComputerMonitor, ComputerScreen и Keyboard сохранены. Добавлены CRT-корпус, подставка и мышь из Unity primitives. Стойка, телефон и маршруты NPC не перемещены. У прежней стойки удалён только компонент `ReceptionInteraction`; новый `ComputerInteraction` находится на экране. Старое окно Reception больше не отображается.

`ReceptionComputer` хранит server-write занятость рабочего места. При входе сервер проверяет наличие игрока, дальность, сторону рабочего места и видимость экрана. Start, check-in и checkout требуют того же User/Lease и близости физического персонажа. Положение сфокусированной камеры не расширяет радиус доступа. Старые и чужие lease отклоняются. Выход, disconnect, закрытие и новый старт смены освобождают компьютер.

Камера локального пользователя интерполируется к **CameraFocus** за 0.3 с в LateUpdate. Root персонажа и CharacterController не перемещаются, FOV не меняется. Локальные `MenuOpen` и `InputSuspended` блокируют WASD/look/другие E-действия; гравитация продолжает работать. Esc плавно восстанавливает local pose, движение и курсор. FirstPersonController не трактует этот Esc как обычное открытие меню подключения. Камеры других игроков не меняются.

UI использует существующую конвенцию проекта — IMGUI. Физические надписи используют текущие TextMesh/WorldServiceText с depth-tested URP material. В M4–M9 нет настроенных TMP-font assets; отдельная система шрифтов не добавлялась. Интерфейс читает живые RoomSnapshot/GuestSnapshot, очередь и счётчики. Независимого management-state нет.

## Телефон, телевизоры и доска

`GuestServiceRequests` остаётся единственным владельцем активного запроса. Snapshot дополнен Kind (CleanTowel/RepairTelevision) и RepairStep. После ответа TV требует два шага: кабель (0→1), регулятор (1→2/Completed). Сервер проверяет RequestId, конкретный NetworkObject комнаты, cycle, Occupied/InRoom, порядок шага и доступность настоящего control collider.

`RoomTelevision` и `TelevisionControl` задают представление и две физические цели. У TV нет отдельного NetworkObject или независимого состояния ремонта. Экран читает общий snapshot: нет питания → нет сигнала → рабочий канал. Отмена снимает временную неисправность. Late join получает актуальное состояние.

Возврат гостя из комнаты отменяет незавершённый запрос, как в M9; полотенца очищаются у всех игроков. Completed не становится missed при возврате. Checkout и смена делают старые запросы невалидными. События другого номера не отменяют текущую заявку.

`StaffTaskBoard` в Utility выводит существующие room/request/shift данные. Собственного списка задач и сетевого состояния нет. Локальное обновление текста раз в 0.2 с не создаёт дополнительного сетевого трафика.

## Статистика и безопасный повтор

Prepared учитывается при Dirty→Ready, Check-in — Ready→Occupied, Checkout — Occupied→Dirty во время Running. Доставка, ремонт и отмена учитываются владельцем запроса после успешной транзакции. Ушедшие по терпению и оставшиеся необслуженными при закрытии гости попадают в Unserved. Отдельно фиксируется Occupied at closing.

В конце смены незавершённый запрос отменяется один раз, итоговый snapshot замораживается. Затем NPC освобождают резервации дверей и возвращаются в скрытый Absent, очередь очищается, комнаты становятся Dirty. Это не позволяет остановленному в проёме NPC запереть игрока. Служебный сброс после Finished не увеличивает Checkouts/Prepared. Обычные задачи больше не принимаются; ходьба, двери и компьютер доступны.

Следующий старт повторно обеспечивает чистое состояние и новые Cycle/RequestId/Guest.Visit. Старые RPC не действуют через границу ночи. Затем создаётся Running snapshot и расписание. Нет NGO Despawn/Respawn пула, накопления гостей, разрыва подключения или системы сохранений.

## Разработка и проверки

- **Tools → Motel → Validate Night Shift M10** открывает сохранённую сцену в preview и проверяет ссылки, позиции очереди, NavMesh, доступность TV, путь камеры и отсутствие пересечений новых примитивов с прежней геометрией. Сохраняет три обзорных рендера.
- **Tools → Motel → Build Current Playtest** выполняет проверки M7/M8/M9/M10 и обновляет постоянный build/launcher. Временные настройки сборки восстанавливаются после BuildPipeline.
- Установка M10 запускается явно; обычный reload не перестраивает сцену. Исторический blockout builder нельзя использовать для регенерации gameplay-сцены.
- `Tests/run_night_test.py [seconds] [--graphics]` запускает настоящие Host/Client и late observer на порту 17790. По умолчанию первая ночь 900 с, следующая 180 с.

Ускоренный тест меняет только Inspector-equivalent параметры до старта, включая patience для проверки очереди из трёх человек. Прогон 900 с сохраняет штатное расписание/терпение и обслуживает первого гостя без искусственного удержания очереди. Первые типы заявок задаются вероятностью, чтобы гарантировать проверку обоих вариантов. Gameplay-state, позиции и deadlines не инъецируются. Игроки ходят через CharacterController; действия используют реальные raycast/RPC, NPC — NavMeshAgent. Файлы `.signal` координируют тестовых игроков, не сетевое состояние игры.

Точные результаты — в `verification.md`. Автотест не доказывает ощущение мыши, плавность изображения и качество звука. Графические кадры подтверждают только видимые состояния.

Ручная проверка: Esc во время обоих переходов камеры, переключение окон, читаемость на своём разрешении, звук телефона, координация и нагрузка за полные 15 минут, свободный проход в очереди, LAN. Намеренно оставьте заявку незавершённой перед checkout. В отдельном прогоне оставьте занятую комнату и заявку к 06:00, затем начните следующую ночь и проверьте сброс.
