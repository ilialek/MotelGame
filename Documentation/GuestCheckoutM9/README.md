# M9 — Guest Checkout & Room Turnover

M9 заменяет временный checkout обычным обслуживанием у Reception в `Assets/Game/Scenes/Motel_Blockout_V3.unity`. Используются существующие NGO, взаимодействие E, комнаты M4, запросы M5, навигация M6–M7 и персонажи M8. Новых пакетов нет.

## Жизненный цикл

`Absent → Arriving → WaitingForCheckIn → WalkingToRoom → InRoom → ReturningForCheckout → WaitingForCheckout → Leaving → Absent`.

Только сервер начинает отсчёт при физическом достижении `GuestIdle`. `GuestLifecycle.stayDuration` / **Stay Duration** задаётся в Inspector; по умолчанию **120 реальных секунд**. Значение есть в `NetworkGuest.prefab` и наследуется пятью настроенными экземплярами сцены. Можно переопределить отдельному гостю. Изменение влияет на следующий вход в InRoom, не перезапускает уже начавшийся таймер. NGO ServerTime использует unscaled time; клиент не инициирует возврат.

При late join подпись гостя обновляется также в `OnNetworkSessionSynchronized`, когда доступны ссылки на остальные NetworkObject.

Дедлайн `StayEndsAt` входит в атомарный `GuestSnapshot`. Когда срок истёк и Reception свободна, сервер ведёт гостя через существующие DoorInside → DoorOutside → ReceptionWaiting. Для прохода используется прежнее резервирование сетевой двери. У стойки гость останавливается и получает надпись `Room XXX — Ready to check out`.

У Reception нажать **E**, затем **Check out — Room XXX / Guest**. Это принимает ключ без отдельного inventory. Кнопка появляется только для ожидающего checkout гостя; `TEST: Check out` больше нет. После подтверждения выводится `Key returned`, гость идёт к ParkingDeparture. По достижении выхода он скрывается и возвращается в существующий ограниченный пул. Как в M7, пять scene NetworkObject остаются зарегистрированными: отдельного NGO Despawn/Respawn и накопления экземпляров нет.

## Комнаты и телефон

До принятия ключа комната остаётся **Occupied**, включая обратный путь и ожидание у стойки. Убирать или заселять её нельзя. Единственная успешная серверная транзакция переводит её в **Dirty** и увеличивает Cycle; сбрасывает кровать, весь мусор, назначение гостя и eligibility запроса. Другие комнаты не меняются. Следующее заселение снова требует **Ready**.

При начале ReturningForCheckout `GuestServiceRequests.ValidateSource` сразу отменяет незавершённый запрос этого гостя и очищает связанные полотенца у игроков. Старые Answer/Take/Deliver RPC дополнительно требуют, чтобы источник всё ещё находился InRoom. Запрос другого номера сохраняется. Completed не отменяется только из-за возврата: сохраняется до обычного выбора следующего запроса либо checkout исходного номера. Выполнение запроса не обязательно для отъезда.

## Reception и авторитетность

Расширен существующий `ReceptionDesk`, отдельной системы очередей нет. Один arriving/check-in/returning/checkout гость резервирует точку обслуживания. После заселения или checkout координатор ждёт, пока гость отойдёт от неё на 2 м. Из истёкших сроков первым выбирается самый ранний дедлайн, затем разрешается очередное прибытие.

Если все комнаты Occupied, новое прибытие откладывается. Это намеренное изменение M7: пятый ожидающий заселения гость иначе блокировал бы возвраты всех четырёх жильцов, а освобождение номера стало бы невозможным. При Dirty/Ready комнате прибывший гость может ждать её подготовки. Игрокам всё равно нужно обслуживать стойку и убирать комнаты; это не автоматическая гостиница.

Checkout RPC проверяет отправителя через прежнюю серверную проверку расстояния/видимости стойки; затем точный NetworkObject гостя, Visit, RoomCycle, WaitingForCheckout, назначение и текущего Occupant. `ServiceRoom.TryCheckout` повторно проверяет соответствие гостя комнате. Повторные, устаревшие, одновременные и чужие запросы не меняют состояние повторно. Телепортаций на маршрутах нет; существующий перенос скрытого гостя к ParkingArrival используется только для следующего визита.

## Ручной Host/Client тест

1. Запустить `Builds/Playtest/LaunchWindowed.command` дважды, расположить окна рядом. В первом **Start Host**, во втором **Start Client**, адрес `127.0.0.1`, порт `7777`. Альтернатива: Host в Unity Play Mode, Client в одном окне того же актуального билда.
2. Клик вне панели подключения захватывает мышь; WASD, Shift, Esc освобождает курсор. E — все взаимодействия. Убрать кровать и мусор в101, у Reception назначить ожидающему гостю Ready номер.
3. Проследить, что гость действительно дошёл до комнаты. Ответить на телефон у стойки, взять полотенце в Utility, доставить к соответствующему номеру. На другом экране проверить синхронизацию.
4. Через120 секунд после достижения комнаты гость готов вернуться. Если стойка занята прибывшим гостем, подготовить ещё один номер и заселить его — возврат начнётся после освобождения стойки.
5. Пока гость идёт обратно или ждёт, номер должен быть Occupied, уборка недоступна. В окне Client нажать E у Reception и выбрать checkout нужного гостя. На обоих экранах номер становится Dirty, кровать и мусор возвращаются; гость уходит пешком на парковку.
6. Убрать этот номер, заселить следующего гостя и повторить. Затем оставить один запрос незавершённым, взять полотенце и убедиться, что оно убирается при начале возврата именно его гостя.
7. Для нескольких жильцов заполнить101–104. Обслужить двоих возвращающихся по очереди; проверить неизменность остальных номеров. Попробовать checkout одновременно в обоих окнах.
8. Подключить ещё один Client во время возврата/ожидания/ухода. Затем отключить Client при ожидании checkout: Host должен суметь принять ключ.

## Проверки и ограничения

Фактические результаты запусков и точный список изменённых файлов находятся в `verification.md` и соседних отчётах. Новый `Tests/run_checkout_test.py` запускает настоящий standalone Host/Client и три поздних подключения на тестовом порту17789; взаимодействия идут через обычные raycast/RPC, NPC ходят сами. Только до регистрации тест меняет Inspector-поле Stay Duration для удобного воспроизведения очередности; состояния/позиции/deadline не подменяются. Один цикл использует штатные120 секунд. Тест включается только явными аргументами Development build. Опция runner `--initial-only` ограничивает повторную проверку первыми checkout102/103 и тремя late join; обычный запуск выполняет также все повторные циклы и disconnect/reconnect.

Исторические M4–M7 smoke-сценарии с принудительным checkout во время InRoom/WalkingToRoom сохранены как тестовые исходники, но их старые ожидания несовместимы с намеренным контрактом M9. Новый end-to-end сценарий покрывает уборку, назначения, доставку, отмену и повторные циклы. Отдельно выполняются прежние проверки сетевых дверей и M8 locomotion/ownership.

Headless тесты не подтверждают плавность изображения, удобство текста/меню, ощущение мыши или звук. Это остаётся ручной проверкой двух окон. Также отдельно проверить LAN между двумя компьютерами. Игрок может физически перекрыть путь гостю — прежняя навигация ждёт освобождения прохода. Нет host migration, сохранения сессии, денег, физического ключа или сложной очереди.
