# M16 — Verification

Проверки выполняются на настоящем Unity 6000.3.19f1 и самостоятельных macOS development-приложениях, не на моках NGO. Старый стабильный Playtest сохранялся до завершения обязательных проверок кандидата.

## Метод

- Native Unity: компиляция, создание/сохранение/повторное открытие новой сцены, NavMesh bake, проверка ссылок и build.
- Встроенный development-only `MotelLayoutSmokeTest` активируется только явными аргументами командной строки. В обычной игре не создаётся.
- Два процесса реально подключаются через NGO/Unity Transport. Третий запускается для late join.
- Персонажи движутся через `CharacterController.Move` с активными коллизиями. Взаимодействия проходят через `PlayerInteractor` raycast и реальные server RPC. Игроки не телепортируются и стены не отключаются.
- Файлы сигналов синхронизируют только тестовые процессы; игровые данные передаются NGO. Проверки ждут сетевое состояние и не считают файл сигналом успешной репликации.
- Управляемые fixtures сокращают интервалы прибытия/пребывания, задают состав багажа и вид заявки, отключают случайные электрические события, когда они мешали бы изолированной проверке. Чистые комнаты в сценариях регистрации готовятся существующей debug-функцией; уборка отдельно проверяется физическими взаимодействиями во всех шести комнатах.
- Combat-проверка сначала наблюдает настоящее проникновение из багажа, затем отдельно ставит существующим debug API контролируемый бой в выбранной ветви. Отступление с сохранённым уроном и летальное поражение проверяются в отдельных боевых fixtures: приманка действует локально и не обязана возвращать ушедшего в другую ветвь Mimic. После диагностического сброса тест повторно берёт возвращённое в Maintenance оружие. Это проверка механик, не доказательство естественного баланса охоты.

Предыдущий Relay-запуск (`relay-20261027-155556`) подключил четыре игрока, но получил UGS Lobby events error 23006 при rejoin. Повтор без изменения сетевого кода прошёл полностью. Это единичное наблюдение; устойчивость внешнего сервиса не гарантируется успешным повтором.

## Исправлено в ходе проверки

1. `NetworkManager` вынесен в root сцены, как требует NGO lifecycle.
2. Новые in-scene NetworkObjects получили независимые сохранённые hash IDs.
3. Устранены разрывы NavMesh у наружных порогов и постоянные отверстия от убираемого мусора.
4. Открытые створки учитываются необязательными динамическими препятствиями.
5. Внутренняя точка ожидания NPC отнесена от зоны движения двери, чтобы checkout не блокировал сам себя.
6. Радиус NavMesh bake увеличен с 0.3 до 0.4 м, сохраняя физические размеры персонажей: запас не позволяет NPC срезать угол западного соединения.
7. Убраны два дублировавшихся участка в скрытых стыках перехода и наложение пола в пороге. Отдельно проверено отсутствие объёмных пересечений между архитектурными стенами и между плитами пола.
8. Третья CCTV-камера перенесена внутрь настоящего северного канала. Рисеры соединены через отверстия в потолках; неиспользуемые торцы каналов закрыты.
9. Исправлены ошибки самого тестового актёра: позиция внутри sweep двери, цель внутри фонарного столба, ожидание уже пройденного промежуточного checkout-состояния и слишком раннее измерение до передачи багажа, ожидание гостя самим тестовым сотрудником прямо в дверном проходе, сброс боевого fixture до подтверждения клиентом урона.

Ранние неуспешные запуски сохранены в `Tests/` для диагностики. Они не являются итоговыми результатами.

## Ручная приёмка

Остаются человеческий playtest темпа ходьбы и повторных маршрутов, читабельность в темноте на разных дисплеях, звук и ощущение управления, одновременные встречи игроков с NPC в дверях, длительная обычная смена со случайными событиями. Автоматический `CharacterController.Move` не является ручной проверкой WASD/мыши. Windows, Steam, искусственные потери пакетов, повышенная задержка и игра на разных физических компьютерах/сетях в M16 не проверялись. Relay проверен через реальные облачные сервисы с процессами на одном Mac.

## Повторный запуск

Сначала собрать candidate: `Tools → Motel → Level V4 → Build validation candidate (Mac)`.

Из папки проекта:

```sh
python3 Documentation/LevelM16/Tools/run_level.py routes
python3 Documentation/LevelM16/Tools/run_level.py service
python3 Documentation/LevelM16/Tools/run_level.py refusal
python3 Documentation/LevelM16/Tools/run_level.py failure
python3 Documentation/LevelM16/Tools/run_level.py hunt --graphics
python3 Documentation/LevelM16/Tools/run_relay.py
```

`--graphics` открывает окна 960×700; без него используются headless-процессы. `--stable` у `run_level.py` проверяет приложение из `Builds/Playtest`. Каждый запуск создаёт отдельную папку результатов. Relay-тест создаёт временные закрытые UGS-сессии и отдельные локальные профили, затем проверяет закрытие и повторное создание сессии.

При продвижении также сохраняется непосредственно заменённое приложение `LivePlaytestBeforePromotion.app` в этой папке. Проверенное приложение — `Builds/Playtest/MotelGame.app`; все существующие `.command` launchers сохраняются побайтно.

`promotion.json` содержит точные пути, успешные наборы и SHA-256 проверенных частей приложения. `preservation-audit.json` сравнивает 2501 ранее существовавший файл с исходным состоянием. `changed-files.txt` перечисляет изменённые и добавленные исходники/ассеты. Автоматические изменения настроек Unity/URP, возникшие от сборки, восстановлены из исходной копии.
