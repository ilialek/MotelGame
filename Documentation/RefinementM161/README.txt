ИЗМЕНЕНИЯ

Багаж проверяется только на физическом анализаторе. Здесь находятся первый
вопрос, загрузка сумки, WEIGH, METAL RESPONSE, CONTROLLED PULSE, уточнения
и история измерений. BALANCE/TILT/LEVEL сохранены в модели, но отсутствуют
в обычном интерфейсе. Подсказка объясняет последовательность и смысл тестов.

Reception показывает общую запись только для чтения, после чего позволяет
Admit/Refuse и назначить номер. Вопросы и измерения с компьютера отклоняются
сервером, включая запрос с подменённым источником. История хранит последние
24 завершённых основных измерения. При смене гостя и новой смене она очищается.
Повторный запрос с тем же номером ревизии не запускает второй тест; намеренное
повторное измерение доступно и добавляется в историю.

Все 14 случаев получили короткие разные истории и ответы. Обычный гость
может забыть штатив или скрыть гантели; механизм и включённый стабилизатор
могут объяснять задержанный отклик. У носителей проверяются противоречия
конкретному объяснению, а не универсальный «признак Mimic». Тихий случай 13
теперь даёт противоречие заявленному весу без убранного теста баланса.
Данные содержимого закрытого багажа и вердикт игроку не показываются.
Авторский разбор со спойлерами: case-review.txt.

Обычная смена длится 900 секунд. Профили на NightShiftController:
Сотрудники | Прибытия | Неисправности | Шанс просьбы за проживание | Готовые номера
1         | 3–4      | 0–1           | 55%                       | 2
2         | 5–6      | 1             | 75%                       | 2
3         | 6–7      | 1–2           | 90%                       | 1
4         | 7–8      | 1–2           | 100%                      | 0

Первое прибытие назначается через 75–90 секунд в одиночку, 60–75 вдвоём,
45–60 втроём/вчетвером; затем гостю ещё нужно дойти от парковки.
Задержка просьбы / пауза после неё: 70/75, 45/40, 30/25, 25/15 секунд
со штатной вариацией. Прибытие можно ненадолго отложить, если есть работа.
Новые неисправности ждут завершения текущих срочных обязанностей; новая
просьба не запускается во время видимого нападения, а в solo — также при
очереди Reception. Действующий запрос не отменяется искусственно.
Бюджет гостей/поломок фиксируется по составу команды в начале смены;
частота будущих просьб и отсрочки учитывают текущих подключённых игроков.
Подготовленные 101/102 — передача предыдущей смены, они не дают очки уборки.
Уборка, полотенца, мусор, ремонт и checkout сохранены. Mimic не появляется
дополнительно в награду за успех: прежний выбор носителя не изменён.

КАК ПРОВЕРИТЬ БЕЗ F8

1. Запустить Builds/Playtest/LaunchWindowed.command. Для solo выбрать
   Local / LAN Debug → Start Host. Для игры через интернет: Create Lobby →
   Copy Code; друг вводит Invite code → Join Lobby; Host нажимает Start Game.
2. Подойти к компьютеру Reception, нажать E → Start Shift. В solo два номера
   уже готовы; не требуется заранее убирать все шесть.
3. Когда гость дойдёт до стойки, E на физическом анализаторе рядом:
   What did you bring? → LOAD THIS GUEST'S BAG → WEIGH. По необходимости
   выполнить METAL RESPONSE и CONTROLLED PULSE, задать уточняющие вопросы.
   Прокрутка открывает оставшиеся ответы и историю. Esc закрывает панель.
4. На Reception открыть Inspection summary. Сравнить ответы и результаты,
   затем Admit → Room ... либо REFUSE ACCOMMODATION. Минимум для заселения:
   первый ответ и взвешивание. Остальные тесты — ваше решение.
5. Вдвоём один сотрудник работает на анализаторе, второй одновременно читает
   сводку на Reception. Проверьте, что новые измерения появляются у обоих.
6. Обслуживать звонки, принять ключ при checkout, убрать кровать и мусор,
   вынести заполненный мешок в контейнер. Номер должен снова стать Ready.
7. При тревоге использовать CCTV и снаряжение из Storage. Для подбора E,
   размещения G, выстрела — левая кнопка мыши. В одном слоте нельзя нести
   одновременно пистолет, приманку и предмет обслуживания.
8. После 06:00 посмотреть итоги и нажать Start Next Shift на Reception.

ПРОВЕРКИ И ОГРАНИЧЕНИЯ
Итоговый журнал: verification.txt. Это автоматические действия в настоящих
экземплярах macOS-игры, а не человеческий playtest. Сервисные и боевые
сценарии используют явно заданные тестовые условия; обычная solo-смена
запускается через Start Shift без изменения длительности и частоты задач.
В solo-проверке скрипт знает авторскую истину и отказывает носителям, чтобы
отдельно измерить темп обслуживания. Это не проверка качества дедукции.

Человеческой проверки требуют понятность ответов, ощущение ритма смены,
звуковой отклик анализатора, боевое напряжение и осмотр всех углов уровня.
Один прогон случайной смены не подтверждает баланс для всех сочетаний.
Relay на нескольких экземплярах одного Mac не заменяет проверку друга
на другом компьютере и другом интернет-подключении.

В текущей среде новый тестовый профиль дважды не вошёл в Unity Authentication:
Curl error 60 / SSL CA certificate error. Сохранённые отдельные профили M16
позволили проверить четыре Relay-подключения, движение, переподключение,
лимит 4, несовместимую версию, новую сессию и возврат после потери Host.
После принудительного завершения Host один клиент зарегистрировал ошибку
UGS SDK «lobby is private / HTTP 403» при обработке запоздавшего события.
Он всё равно вернулся в меню, но весь Relay-прогон не считается чистым PASS.
Проверка сертификатов, обработчики SDK и сетевой протокол транспорта не
менялись. Эти два ограничения остаются для отдельной проверки онлайн.
