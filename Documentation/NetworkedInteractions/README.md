> С M7 используется один актуальный build: `Builds/Playtest/LaunchWindowed.command`. Это историческое описание milestone; текущие многокомнатный сценарий и тесты находятся в `Documentation/MultipleGuestsM7/README.md`. Оба участника должны запускать текущую версию. Старые M4–M6 single-guest тесты сохранены как история и не проверяют текущий M7 protocol.
Unity 6000.3.19f1 · Netcode for GameObjects 2.13.3 · Unity Transport 2.6.0.
Пакеты не менялись.

## Реализация

В `Motel/Rooms/Room101` статическая заглушка `Door_parked_open_90deg` заменена экземпляром `NetworkDoor.prefab` с именем `Room101Door`.
Петля: (20.58, 0, 13.16). Полотно: 0.05 × 2.15 × 1.02 м в существующем проёме 1.1 × 2.2 м. Поворот 0 → +90° за 0.65 секунды внутрь номера. Используются существующие Door и Metal materials.

`PlayerInteractor` выполняет raycast из камеры владельца на 2.5 м, показывает «Press E» и обрабатывает E. Компонент выключен у удалённых игроков; дополнительная проверка ownership исключает их raycasts. `IInteractable` содержит только доступность и вызов взаимодействия.

`NetworkDoor` хранит атомарный `NetworkVariable<DoorState>`: целевое Open и серверное время начала перехода. Запись разрешена серверу. RPC разрешён любому подключённому клиенту через `RpcInvokePermission.Everyone`, но сервер сам определяет отправителя и проверяет существование его игрока, расстояние от глаз до полотна, отсутствие препятствия и завершение предыдущей анимации. Запросы во время движения отбрасываются, а не ставятся в очередь. Игрок в зоне взмаха также блокирует начало перехода.

Угол и локальный collider вычисляются по NGO ServerTime со smoothstep; NetworkTransform на двери отсутствует. Позднее подключение сразу получает актуальное состояние и фазу перехода. Проверялось подключение после завершённого открывания.

## Ручная проверка

1. Открыть `Assets/Game/Scenes/Motel_Blockout_V3.unity`, включить Play Mode, нажать **Start Host**.
2. Запустить `Builds/Playtest/MotelGame.app`. Адрес `127.0.0.1`, порт `7777`, нажать **Start Client**. Для LAN указать IP компьютера хоста.
3. Щёлкнуть вне меню для захвата курсора. WASD / мышь / Left Shift; Esc освобождает курсор.
4. Из лобби пройти прямо в коридор справа от reception, затем повернуть налево к номерам. Подойти к Room 101 со стороны коридора, навести центр камеры на полотно с расстояния примерно 1–2 м.
5. Убедиться, что появилась **Press E**. Нажать E на хосте, проверить плавное открывание в обоих окнах. Пройти внутрь и отойти от зоны движения полотна.
6. Клиентом навести камеру на открытую дверь и нажать E. Проверить закрывание в обоих окнах. Проверить коллизию закрытой двери и проход через открытую каждым игроком.
7. Быстро нажимать E: во время анимации новые запросы игнорируются. После окончания следующий запрос меняет состояние.
8. Открыть дверь, отключить клиент и подключить снова: дверь должна остаться открытой.

Для пересборки использовать **Tools → Motel → Build Networked Interactions Development Player**: эта команда включает только нужную motel scene. Обычная сборка через Build Profiles использует пользовательский список сцен, где SampleScene может стоять первой.

## Выполненные проверки

- Unity импортировала и сохранила prefab и сцену. Нативная проверка поворота 0–90° с шагом 1° не нашла проникновения полотна в статические colliders.
- CharacterController 1.8 × 0.6 м в копии сцены: закрытая дверь блокирует проход, открытая пропускает.
- Дополнительная SAT-проверка по сохранённой геометрии, шаг 0.1°, полотно и обе ручки: 2703 проверки без пересечений.
- Финальная macOS Development-сборка: Succeeded, 0 errors, 0 warnings.
- Два реальных standalone-процесса через NGO/UTP localhost; затем первый клиент отключён и запущен новый для late join. Отчёты находятся в `run-20261014-130336/`.
- Синтетическое движение локальных CharacterController до Room 101; ownership камеры, движения и interactor; запрет raycasts удалённого игрока.
- Реальный raycast и вызов interaction/RPC: хост открыл, клиент наблюдал промежуточные углы, клиент закрыл, хост получил закрытое состояние.
- Закрытая дверь блокировала локальную капсулу и хоста, и клиента. Хост прошёл через открытую дверь.
- Прямой RPC клиента из лобби отклонён сервером.
- 20 RPC подряд дали один переход и стабильное открытое состояние.
- Late join получил открытое состояние и угол 90°. Disconnect завершился штатно. Критических runtime error/exception/assert в тестовых логах нет.

Тест запускался с `-batchmode -nographics`: отрисовка подсказки, физическое нажатие E, визуальная плавность при обычной частоте кадров и Editor + standalone вручную ещё не проверены. Автотест вызывает тот же raycast/interaction/RPC, но не эмулирует клавиатуру. LAN, задержки и потеря пакетов не тестировались.

`NetworkDoorSmokeTest` включается только в Editor/development build и только явным аргументом `-motel-door-test host|client|late -motel-door-results <directory>`. Файлы-сигналы координируют шаги; состояние двери и удалённые позиции наблюдаются через NGO. Без аргументов тест не запускается. В release build он исключён.

## Сохранность и ограничения

Backup: `Backups/BeforeNetworkedDoor_20261014_125906/`. Содержит прежнюю сцену, player prefab, registry, изменяемые scripts/spec и настройки до сборки. Git также сохраняет исходное состояние; коммит не создавался.

Сравнение всех прежних документов scene YAML: изменён только список детей Room101, удалены пять документов статической заглушки и добавлена новая prefab instance. Все остальные существовавшие объекты сцены идентичны. Материалы, свет, мебель, layout, SampleScene, FPC и package-файлы не изменены. См. `preservation-validation.json`.

- Зона взмаха проверяется консервативно перед началом движения. Если игрок стоит вплотную к полотну или в этой зоне, нужно отойти. Отдельной подсказки причины отказа пока нет.
- Это кинематически вращаемый BoxCollider, не физическая дверь с защитой от зажатия. Игрок, вошедший в зону уже во время движения, может получить нежелательное выталкивание/пересечение; проверить вручную двумя игроками.
- Локальные colliders следуют серверному времени, но сетевые задержки могут давать кратковременное различие фаз. Lag compensation не добавлялась.
- Distance validation использует серверную копию owner-authoritative player position; это не защита от модифицированного клиента, телепортирующего своего персонажа.
- Статическая layout specification больше не содержит Room101-заглушку. Проверки builder исключают сетевую дверь из количества статических примитивов. Полная регенерация старым blockout builder не является способом сохранить gameplay-компоненты; используйте текущую сцену.
