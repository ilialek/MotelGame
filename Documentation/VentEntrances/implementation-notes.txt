WALL VENT ENTRANCES — implementation notes

Existing scene: Assets/Game/Scenes/Motel_Layout_V4.unity

Six wall grilles replace the former floor hatches. The existing VentHatch script GUID and NetworkObject identities are retained; the component now controls only a hinged leaf. E uses the existing IInteractable/PlayerInteractor path. The server validates reach, incapacitation, revision and hinge sweep occupancy. Recessed grilles additionally test their visible centre when the closest upper edge is occluded by the lintel, so opening while standing works. The optional useCenter argument defaults to false for all existing ServiceInteractionValidation callers. A replicated state contains Open, Revision, StartedAt and FromAngle. Both sides animate from synchronized NGO time over 0.55 seconds. Concurrent/repeated stale requests cannot toggle twice. A blocked closing sweep is rejected; an actor entering an active closing sweep causes it to reopen from its current angle. No input, position setter, teleport, reservation, auto-climb or movement command exists in the grille component.

FirstPersonController retains WASD, mouse, crouch, sprint, gravity, collision, flashlight and pistol integration. Removed the legacy automatic ventPath traversal and cancellation. The normal movement calculation is in one private MovePlayer method, used by Update; the development route test invokes that same method with deterministic forward input in background windows. Route marker transforms in VentHatch are authoring/verification data, never consumed by production player movement. NetworkPlayer's crouch validation now relies on actual headroom instead of a hatch transit reservation.

Authoring / future maintenance
- VentEntranceSetup performs a one-shot migration guarded against reapplying it to the migrated scene. The previous floor-hatch refinement is retired. Use the backed-up scene to reproduce migration; do not rerun legacy Install on the active level.
- Existing UndergroundSetup validation/build workflow calls the new physical-route validator. Builds go to a separate VentEntranceFinal folder and are promoted to UndergroundCandidate only after verification.
- Online compatibility string is motel-underground-2 because the scene component's replicated state changed. No transport or Relay logic changed; all participants need this version.
- No packages installed; no networking framework, gameplay system, Mimic change, new lighting or Git commit.

Rollback
For an immediate playable rollback, launch Builds/UndergroundBeforeWallVents_20261031/LaunchWindowed.command (same app also retained in the BeforeWallVents backup). To roll back the Unity project, close Play Mode/Editor; restore the modified pre-existing C# files and Motel_Layout_V4.unity from the backup, remove the newly added Assets/Game/Editor/VentEntranceSetup.cs and its .meta, and optionally remove only Assets/Game/Geometry/VentEntrances/ plus its .meta. Do not delete the parent Geometry folder or unrelated files. The list of modified-files.txt identifies the existing scripts; all are backed up under their original relative paths. Refresh Unity after restoring. Packages, settings, prefabs and the baked NavMesh were not changed and need no rollback.
